# Telegram-бот для заполнения договоров

Бот берёт один из DOCX-договоров в репозитории, принимает от пользователя реквизиты и условия свободным текстом, автоматически составляет план замен через OpenAI API и отправляет готовый PDF-файл.

Также сохранён ручной режим: можно отправлять точные замены в формате `старый текст => новый текст`.

## Что умеет бот

- здоровается по команде `/start`;
- опционально отправляет приветствие в заданный чат при запуске процесса;
- показывает список доступных `.docx`-шаблонов;
- принимает реквизиты, сумму, дату, номер договора и другие данные свободным текстом;
- через OpenAI API определяет, какие фрагменты договора нужно заменить;
- заменяет текст в абзацах, таблицах, колонтитулах DOCX;
- конвертирует готовый DOCX в PDF через LibreOffice;
- отправляет пользователю PDF, а если PDF-конвертация недоступна — DOCX с предупреждением;
- сообщает, какие исходные фразы не были найдены в документе;
- может ограничивать доступ по Telegram ID.

## Файлы договоров

Сейчас в репозитории доступны шаблоны:

- `Арена-тех2(1).docx`
- `Договор Подкаст.docx`
- `Договор пиар.docx`
- `Договор_БизнесИнсайтер.docx`
- `гусопт.docx`

Новые шаблоны можно добавлять в корень репозитория или в отдельную папку, указав её в `TEMPLATE_DIR`.

## Настройка

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.
2. Создайте OpenAI API key для автоматического понимания свободного текста.
3. Скопируйте пример переменных окружения:

   ```bash
   cp .env.example .env
   ```

4. Откройте `.env` и заполните значения:

   ```env
   BOT_TOKEN=ваш_новый_токен_от_BotFather
   OPENAI_API_KEY=ваш_openai_api_key
   OPENAI_MODEL=gpt-5.5
   OUTPUT_FORMAT=pdf
   TEMPLATE_DIR=.
   GENERATED_DIR=generated
   ```

5. По желанию ограничьте доступ к боту:

   ```env
   ALLOWED_USER_IDS=111111111,222222222
   ```

   Узнать свой Telegram ID можно через специальных ботов вроде `@userinfobot`.

6. Если хотите, чтобы бот писал вам «я запущен» сразу после старта процесса, укажите чат:

   ```env
   STARTUP_CHAT_ID=111111111
   ```

   Перед этим пользователь с таким ID должен хотя бы один раз открыть бота в Telegram.

## PDF-конвертация

Для PDF нужен LibreOffice на сервере или компьютере, где запущен бот.

### Ubuntu / Debian

```bash
sudo apt-get update
sudo apt-get install -y libreoffice
```

Если LibreOffice не установлен, бот всё равно заполнит договор, но отправит DOCX и напишет предупреждение, что PDF не создан.

Если PDF временно не нужен, в `.env` можно указать:

```env
OUTPUT_FORMAT=docx
```

## Запуск локально

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m bot.main
```

## Как пользоваться в Telegram

1. Отправьте боту команду:

   ```text
   /start
   ```

2. Выберите договор:

   ```text
   /templates
   ```

3. Отправьте данные свободным текстом. Например:

   ```text
   Контрагент: ООО «Ромашка».
   ИНН 7700000000, КПП 770001001.
   Юридический адрес: 109000, Москва, ул. Примерная, д. 1.
   Договор № 15/2026 от 29.05.2026.
   Сумма 150 000 рублей, без НДС.
   Подписант: Иванов Иван Иванович, генеральный директор, действует на основании устава.
   ```

4. Бот проанализирует выбранный договор, составит замены, заполнит файл и пришлёт PDF.

## Ручной режим точных замен

Если нужно заменить строго конкретный текст, отправьте каждую замену отдельной строкой:

```text
старый текст => новый текст
№ 1 от 01.01.2026 => № 15 от 29.05.2026
100 000 рублей => 150 000 рублей
ООО «Старое» => ООО «Новое»
```

Поддерживаются разделители:

- `=>`
- `->`
- `=`
- `:`

Лучше использовать `=>`, потому что этот разделитель реже встречается внутри текста договора.

## Важные ограничения

- Автоматическое понимание свободного текста требует `OPENAI_API_KEY`.
- Чем точнее пользователь описывает реквизиты и условия, тем лучше план замен.
- Бот заменяет только те фрагменты, которые смог сопоставить с текстом выбранного договора.
- Если Word разбил одну фразу на несколько внутренних фрагментов форматирования, бот всё равно попробует заменить её, но форматирование внутри изменённого абзаца может стать проще.
- Не публикуйте настоящий Telegram-токен и OpenAI API key в GitHub. Храните их только в `.env` или переменных окружения сервера.

## Если токен уже был отправлен в чат или опубликован

Токен Telegram-бота даёт полный доступ к управлению ботом. Его нельзя коммитить в GitHub, отправлять в публичные чаты или хранить в README.

Если токен был случайно раскрыт:

1. Откройте [@BotFather](https://t.me/BotFather).
2. Выполните команду `/revoke` или зайдите в настройки нужного бота.
3. Выпустите новый токен.
4. Запишите новый токен только в локальный `.env` или в переменные окружения сервера.
5. Перезапустите бота.

Пример локального `.env`:

```env
BOT_TOKEN=новый_токен_от_BotFather
OPENAI_API_KEY=ваш_openai_api_key
ALLOWED_USER_IDS=ваш_telegram_id
TEMPLATE_DIR=.
GENERATED_DIR=generated
OUTPUT_FORMAT=pdf
```

Файл `.env` уже добавлен в `.gitignore`, поэтому он не должен попадать в Git.
